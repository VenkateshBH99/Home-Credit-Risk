\section{Dataset Overview}
\label{sec:dataset_overview}

The primary dataset is the Home Credit Default Risk competition dataset hosted on Kaggle~\cite{kaggle2018}, comprising real-world consumer lending data from Home Credit Group's operations in Southeast Asia. The dataset contains 307,511 labelled loan applications across 7 interlinked relational tables totalling over 55 million supplementary records. This scale and relational complexity make the dataset particularly suitable for investigating whether alternative behavioural data can improve credit default prediction beyond what traditional application-only variables offer.

\subsection{Physical Data Model}

The relational structure of the dataset is illustrated in Figure~\ref{fig:data_model}. The central entity is the application table, which connects to supplementary tables through two levels of foreign keys: \texttt{SK\_ID\_CURR} links applicants to their bureau records and previous Home Credit applications, while \texttt{SK\_ID\_BUREAU} and \texttt{SK\_ID\_PREV} link these intermediate tables to their respective granular balance and payment histories.

\ProjectFigure[!htbp][width=0.85\textwidth]{discussion/Physical data model - Table_Relations_home_credit.png}{Dataset Relationship Map}{Physical Data Model showing the relational structure of the Home Credit dataset. Tables are linked through \texttt{SK\_ID\_CURR} (applicant identifier), \texttt{SK\_ID\_PREV} (previous application identifier), and \texttt{SK\_ID\_BUREAU} (bureau record identifier).}{fig:data_model}


\subsection{Relational Linkage}

The relational structure follows a hierarchical pattern with two primary branches:

\begin{itemize}
    \item \textbf{External bureau branch:} \texttt{application\_train/test} $\xrightarrow{\texttt{SK\_ID\_CURR}}$ \texttt{bureau} $\xrightarrow{\texttt{SK\_ID\_BUREAU}}$ \texttt{bureau\_balance}
    \item \textbf{Internal behavioural branch:}
    \begin{itemize}
        \item \texttt{application\_train/test} $\xrightarrow{\texttt{SK\_ID\_CURR}}$ \texttt{previous\_application} $\xrightarrow{\texttt{SK\_ID\_PREV}}$ \texttt{POS\_CASH\_balance}
        \item \texttt{application\_train/test} $\xrightarrow{\texttt{SK\_ID\_CURR}}$ \texttt{previous\_application} $\xrightarrow{\texttt{SK\_ID\_PREV}}$ \texttt{credit\_card\_balance}
        \item \texttt{application\_train/test} $\xrightarrow{\texttt{SK\_ID\_CURR}}$ \texttt{previous\_application} $\xrightarrow{\texttt{SK\_ID\_PREV}}$ \texttt{installments\_payments}
    \end{itemize}
\end{itemize}

This two-branch structure means that the model can draw on both external credit bureau information (how the applicant has behaved with other lenders) and internal Home Credit behavioural data (how the applicant has behaved with Home Credit's own products). The aggregation challenge---collapsing millions of monthly records into applicant-level features---is addressed in Chapter~\ref{chap:feature_engineering}.

\section{Data Quality Analysis}
\label{sec:data_quality}

\subsection{Missing Value Analysis}

The dataset exhibits substantial missingness, with 67 out of 122 features in the application table containing missing values and 49 features having more than 40\% missing data. Figure~\ref{fig:data_quality_1} summarises the missing value profile across the application table.

\ProjectFigure[!htbp][width=0.9\textwidth]{pptx/data quality analysis - table1.png}{Missingness Summary I}{Data Quality Analysis -- Missing Value Summary across the application table. Features are ranked by missingness percentage.}{fig:data_quality_1}


\ProjectFigure[!htbp][width=0.9\textwidth]{pptx/data quality analysis - table2.png}{Missingness Summary II}{Data Quality Analysis -- Continuation of missing value summary showing features with moderate to low missingness.}{fig:data_quality_2}


Missing values are not randomly distributed but are concentrated in specific groups of variables, particularly those related to building characteristics (approximately 70\% missing), external scores, and bureau information. This non-random missingness pattern suggests that the absence of data may itself carry predictive information. For instance, the absence of external score data could indicate a lack of formal credit history, which is often associated with higher default risk among thin-file applicants.

\ProjectFigure[!htbp][width=0.85\textwidth]{notebook/home_credit_eda_4_missing_values_analysis_2.png}{Missingness Pattern Overview}{Detailed missing values analysis from the EDA notebook, showing the distribution and pattern of missingness across all features.}{fig:missing_values_eda}


The imputation strategy was tailored to each variable group:
\begin{itemize}
    \item \textbf{Building-related features} (approximately 70\% missing): dropped entirely to avoid introducing excessive noise.
    \item \textbf{EXT\_SOURCE\_1} (approximately 56.4\% missing): imputed using the median, with a binary missingness indicator retained.
    \item \textbf{Remaining numerical features}: median imputation to mitigate outlier influence.
    \item \textbf{Categorical features}: mode imputation to maintain the most frequent class.
\end{itemize}

\subsection{DAYS\_EMPLOYED Anomaly}

A notable anomaly was discovered in the \texttt{DAYS\_EMPLOYED} variable, where a sentinel value of 365,243 appears in approximately 18\% of records. This value corresponds to an unrealistic employment duration of approximately 1,000 years and likely represents missing or placeholder data inserted during the data collection process.

\ProjectFigure[!htbp][width=0.85\textwidth]{notebook/home_credit_eda_days_employed_analysis_detect__13.png}{DAYS\_EMPLOYED Anomaly}{Employment duration distribution before and after anomaly treatment. The spike at 365,243 days (approximately 18\% of records) is clearly visible in the pre-treatment distribution.}{fig:days_employed_anomaly}


Interestingly, the anomalous group exhibits a \textit{lower} default rate compared to the rest of the dataset, suggesting that the placeholder value may implicitly encode a specific applicant segment (e.g., pensioners or self-employed individuals). These values were replaced with \texttt{NaN} and a separate binary indicator (\texttt{DAYS\_EMPLOYED\_ANOMALY}) was created to preserve any predictive signal while preventing distributional distortion.

\subsection{Outlier Treatment}

Financial variables such as \texttt{AMT\_INCOME\_TOTAL}, \texttt{AMT\_CREDIT}, and \texttt{AMT\_ANNUITY} exhibit significant right-skew with extreme outlier values.

\ProjectFigure[!htbp][width=0.85\textwidth]{notebook/home_credit_eda_8_outlier_detection_with_box_p_15.png}{Financial Outlier Boxplots}{Boxplots of key financial features showing outlier profiles. Income and credit amount variables exhibit heavy right tails.}{fig:outlier_boxplots}


Outlier treatment was performed via winsorisation at the 1st and 99th percentiles for highly skewed financial features. While tree-based models (Random Forest, XGBoost, LightGBM) are inherently more robust to outliers due to their split-based decision rules, appropriate preprocessing reduces the impact on the logistic regression baseline and improves feature scaling consistency across all model families.

\section{Exploratory Data Analysis}
\label{sec:eda}

\subsection{Target Variable Analysis}
\label{subsec:target_analysis}

The target variable represents the binary outcome of loan repayment, where 1 indicates default and 0 indicates non-default. The dataset exhibits a pronounced class imbalance with only 8.07\% of observations belonging to the default class---a ratio of approximately 1:11.4.

\ProjectFigure[!htbp][width=0.5\textwidth]{pptx/quick summary stats - default vs no default donut.png}{Target Class Balance}{Target variable distribution showing 8.07\% default rate (24,825 defaults out of 307,511 applications). The 1:11.4 class ratio necessitates specialised handling during model training.}{fig:target_dist}


This imbalance has critical implications for both modelling and evaluation. Standard accuracy metrics become unreliable, as a model can achieve 92\% accuracy simply by predicting the majority class. Consequently, evaluation metrics such as AUC-ROC, KS statistic, and recall are more appropriate, as they focus on the model's ability to distinguish between classes rather than overall correctness. From a business perspective, the imbalance reflects real-world credit portfolios where defaults are relatively rare but financially significant---a single undetected default can cost 10--50$\times$ the profit from a performing loan.

The class imbalance handling strategies employed across the modelling experiments are detailed in Chapter~\ref{chap:modeling} and include class weighting (\texttt{class\_weight='balanced'} for scikit-learn models), \texttt{scale\_pos\_weight} for gradient boosting frameworks, and ensemble undersampling approaches.

\subsubsection{Interpretation of External Scores}

The external source variables are anonymised in the original dataset with no official documentation of their provenance. Through analysis of data characteristics---including missing rates, unique value counts, correlations with other features, and distributional properties---the following interpretations are offered:

\begin{table}[H]
\centering
\caption{Interpretation of External Source Scores Based on Data Characteristics}
\label{tab:ext_source_interp}
\begin{tabular}{p{2.5cm}p{2cm}p{2cm}p{2cm}p{4.5cm}}
\toprule
\textbf{Feature} & \textbf{Missing \%} & \textbf{Unique Values} & \textbf{Correlation with TARGET} & \textbf{Likely Interpretation} \\
\midrule
EXT\_SOURCE\_1 & 56.4\% & 114K & $r = -0.155$ & Private credit bureau probabilistic score \\
EXT\_SOURCE\_2 & 0.2\% & 119K & $r = -0.161$ & Telco or digital footprint score \\
EXT\_SOURCE\_3 & 19.8\% & 814 & $r = -0.179$ & Government or public credit score band \\
\bottomrule
\end{tabular}
\end{table}

\begin{itemize}
    \item \textbf{EXT\_SOURCE\_1} (56.4\% missing, 114K unique values): Likely a \textit{private credit bureau probabilistic score}. Its high missing rate aligns with developing regions where private bureau coverage is limited. It has a strong correlation with age (\texttt{DAYS\_BIRTH}), consistent with stability-based scoring where a 65-year-old scores nearly 3$\times$ higher than a 22-year-old on average.

    \item \textbf{EXT\_SOURCE\_2} (0.2\% missing, 119K unique values): Almost certainly a \textit{telco or digital footprint score}. With 98\% coverage including applicants with zero payment history, this is a near-universal signal. Defaulters show lower, flatter usage patterns while non-defaulters show higher data engagement.

    \item \textbf{EXT\_SOURCE\_3} (19.8\% missing, 814 unique values): Likely a \textit{government or public credit score band}. The small number of unique values indicates a banded/bucketed scoring system. It has the strongest negative correlation with default ($r = -0.179$) and aligns well with days-past-due patterns in bureau data.
\end{itemize}

\ProjectFigure[!htbp][width=0.85\textwidth]{discussion/missing values for ext sources.png}{Missing value patterns for external source variables}{Missing value patterns for external source variables. The differential missingness rates support the interpretation of each score as originating from distinct data providers with varying coverage.}{fig:ext_source_missing}


These interpretations are important because the external scores represent alternative data proxies that can extend credit assessment to thin-file borrowers. \texttt{EXT\_SOURCE\_2}, with its near-universal coverage, is particularly valuable for applicants who lack traditional bureau records.

The correlation analysis yields several important findings:
\begin{enumerate}
    \item External score variables exhibit the strongest correlations with default (all negative, $|r| = 0.155\text{--}0.179$).

\end{enumerate}

The previous application dataset contains 1.67 million records covering 94.6\% of applicants, capturing historical borrowing patterns within Home Credit's own product ecosystem.

\subsection{Internal Behavioural Data Analysis}
\label{subsec:behavioural_eda}

Internal behavioural tables capture how borrowers actually repay loans after origination, providing a dynamic picture of repayment discipline, utilisation, and timing. Together, these three tables produce 85 applicant-level features after aggregation that, when combined with application data, improve prediction accuracy by approximately 3.1\%.

\subsubsection{POS Cash Balance}

The POS Cash Balance table contains approximately 10 million records covering 94.1\% of applicants, tracking monthly instalment behaviour on point-of-sale and cash loans.

\ProjectFigure*[!htbp][width=0.85\textwidth]{notebook/home_credit_eda_13_pos_cash_balance_analysis_29.png}{Remaining Installments Over Time}{Detailed POS Cash Balance analysis showing average remaining instalments over time. The curve peaks mid-lifecycle and then declines as accounts mature toward closure.}{fig:pos_cash_detailed}


The analysis found that nearly all payments were on time, with overdue cases comprising only 0.3\% of records. This suggests that POS repayment histories are mostly stable, but when aggregated they still provide meaningful variation across borrowers that contributes to risk differentiation.

\subsubsection{Credit Card Balance}

The Credit Card Balance table contains approximately 3.84 million records but covers only 28.3\% of applicants, making it the most selective of the behavioural tables.

\ProjectFigure*[!htbp][width=0.85\textwidth]{notebook/home_credit_eda_14_credit_card_balance_analysi_31.png}{Credit Card Balance Over Time}{Detailed credit card balance analysis showing average card balance over time. The balance trough around month -40 and the sharp rise toward the most recent months suggest changing utilisation behaviour as accounts mature.}{fig:credit_card_detailed}


Despite its lower coverage, the credit card data contributes useful information on card utilisation and repayment behaviour. Utilisation ratios average 30--50\%, and overdue cases are rare at approximately 0.2\%. The limited coverage means that missingness in credit card features carries implicit information about the applicant's product usage profile.

\subsubsection{Installments Payments}

The Installments Payments table contains approximately 13.6 million records covering 94.8\% of applicants, recording each individual loan repayment event.

\ProjectFigure*[!htbp][width=0.85\textwidth]{notebook/home_credit_eda_15_installments_payments_analy_33.png}{Payment Delay by Version}{Detailed instalment payment analysis showing average payment delay by instalment version. Approximately 5--10\% of payments are late, with an average delay of 5--10 days. These late-payment patterns are more directly linked to repayment reliability than the POS or credit card data and therefore represent the most valuable behavioural indicators for risk modelling. Engineered features from this table include late-payment ratios, average delay days, payment-to-instalment discrepancies, and monthly delinquency frequency.

\section{Data Preprocessing Pipeline}
\label{sec:preprocessing}

The preprocessing pipeline was implemented as a modular Python module (\texttt{pipelines/preprocessing\_pipeline.py}) that enforces strict anti-leakage protocols and produces four downstream-ready dataset variants.

\subsection{Imputation Strategy}

\begin{itemize}
    \item \textbf{Numerical features:} Median imputation, fitted on the training split only, to mitigate the impact of outliers while preserving distributional central tendency.
    \item \textbf{Categorical features:} Mode imputation to maintain the most frequent class. Unseen categories in validation/test splits are mapped to a fallback value.
    \item \textbf{High-missingness features:} Columns with more than 70\% missing values were removed entirely to avoid introducing excessive noise.
    \item \textbf{Missingness indicators:} Binary flags were retained for features where missingness carries potential predictive information (e.g., \texttt{EXT\_SOURCE\_1}).
\end{itemize}

\subsection{Feature Encoding}

Categorical features were encoded using two strategies depending on the modelling context:
\begin{itemize}
    \item \textbf{One-hot encoding:} Applied to application-level categorical features using \texttt{pd.get\_dummies}, expanding the feature space to capture all category levels explicitly.
    \item \textbf{Label encoding:} Applied to remaining categorical features in the combined dataset with unseen-value fallback, providing a compact representation suitable for tree-based models.
\end{itemize}

All numerical features were scaled using \texttt{StandardScaler} (zero mean, unit variance), fitted on the training split only.

\subsection{Anti-Leakage Design}

The modular pipeline enforces a strict anti-leakage protocol:
\begin{enumerate}
    \item \textbf{Split-first:} Train/validation/test splits (70\%/15\%/15\%) are created before any preprocessing transformations.
    \item \textbf{Fit-on-train:} All imputers, scalers, encoders, and PCA objects are fitted exclusively on the training split.
    \item \textbf{Transform-all:} Fitted transformers are applied identically to validation and test splits without refitting.
\end{enumerate}

This design prevents information from future data influencing model training, a critical requirement for honest model evaluation and a common source of inflated performance in credit scoring research.
